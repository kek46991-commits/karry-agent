# URL解析：取得1回＋提案生成1回

単一のWebページを解析・要約・改善提案する依頼では、従来の検索やコマンドの繰り返しを避ける短縮経路を使います。**fetch_and_summarize_urlを1回実行し、その結果をツールなしのモデル生成へ1回渡して終了**します。正常時は `steps=2`、`tool_calls=1`、`metrics.api_calls=1`。短縮経路の提案生成は再試行せず1試行に固定し、モデル失敗時は `failed` を返します。一般ループの既存再試行は維持します。

実行ステップは論理的な処理回数で、応答秒数ではありません。モデルの応答時間や対象サイトの速度は別です。HTML取得は約10秒の全体期限、接続・読み取りにも短いタイムアウトを設け、再検索・再取得ループへは入りません。リダイレクトは最大3回で、その分のHTTPリクエストは発生します。

## 使い方

CLIと `/chat`、`/run`、`/agent/run` の共通AgentCoreで使えます。単独のURL、または単一URLと短い解析・要約・提案の依頼が短縮対象です。

```text
https://example.com/
```

```text
このURLを解析して改善提案してください https://example.com/
```

会話履歴が付くAPIでも、短縮経路の判定は **今回の依頼** を使い、履歴は回答生成用に保持します。複数URLの比較、予定登録、画像生成、ファイル保存などの複合操作は無条件に短縮経路へ置き換えません。自由文で判定対象外の場合も、一般ループにはこの取得ツールを優先する指示を追加しています。一般経路の呼び出し数が必ず2以下になることまでは保証しません。

直接ツールAPIにも同じツールを登録しています。認証ヘッダーは設定済みBearerトークンを使用してください。

```json
{
  "tool_name": "fetch_and_summarize_url",
  "arguments": {"url": "https://example.com/"}
}
```

送信先は `POST /api/agent/tools/execute`。返却の `result.status` と `result.error` を確認してください。HTTP 200だけで取得成功とはしません。

## 抽出内容

HTMLを1回解析し、タイトル、meta description、本文最大3,000文字、見出し最大10件、JSON-LDの型名だけを返します。script、style、nav、footer、iframe、非表示要素等を除去し、main/articleを優先します。HTML全文やJSON-LD全文はモデルへ渡しません。抽出自体はLLMを呼ばず、要約・改善提案は最後のモデル生成で行います。

静的HTMLまたはtext/plainのみが対象です。画像、CSS、JavaScriptはダウンロード・実行せず、巡回もしません。本文なしの動的ページは `needs_user_action` で本文・スクリーンショットの共有を求めます。ログイン、CAPTCHA、PDF、動画、スクリーンショット解析の自動代替経路は追加していません。取得済みの本文しかない場合、見た目や画像を確認したと説明しない指示をモデルへ渡します。

取得失敗はツール結果付きで `failed` を返し、モデルを呼びません。最終回答に関数呼び出しが混じっても実行せず `failed` とします。

## 上限と認証

一般自律ループの既定値は8から20へ変更しました。環境変数 `KARRY_MAX_TOOL_STEPS` で1～50の整数に変更できます。明示的な `AgentCore(max_steps=...)` を優先します。不正値は起動・初期化エラーとなり、無制限にしません。短縮経路を利用する場合は2以上にしてください。1の場合は取得後 `limit_reached` で終了し、提案生成しません。

```dotenv
KARRY_MAX_TOOL_STEPS=20
```

既存のBearer認証、private_mode、呼称環境変数、Calendar確認フロー、Self-Healingのパッチ生成・公開設定は変えません。取得したWebコンテンツは信頼しないデータとして扱い、短縮経路の提案生成にはツール宣言を渡しません。

取得先は公開HTTP(S)の標準ポートのみ。内部・非公開IP、混在したDNS回答、URL中のユーザー認証情報を拒否し、各転送先も再検証します。検証済みの数値IPへ直接接続し、HTTPSは元のホスト名でSNIと証明書を検証します。名前解決は期限付きの独立プロセスで行い、タイムアウト時は終了・回収して枯渇を避けます。本文読み取りごとに残り時間をソケットへ反映します。環境のプロキシ、APIトークン、Cookieは送信しません。応答容量は1 MiB、対応しない圧縮・Content-Typeは明示失敗です。

## 実装と参照

`url_analysis.py` が取得・抽出・短縮判定、`config.py` が上限設定、`core.py` が短縮実行と提案生成、`tools.py` が共通登録、`app.py` が今回の依頼と履歴の分離を担当します。既存レジストリは同期関数を使用し、必要な非同期連携には `fetch_and_summarize_url_async` を提供します。

HTML解析には [Beautiful Soup](https://www.crummy.com/software/BeautifulSoup/bs4/doc/)、接続には [urllib3](https://github.com/urllib3/urllib3) を再利用しています。DNS固定接続とTLSホスト名検証は [urllib3公式ドキュメント](https://urllib3.readthedocs.io/en/stable/advanced-usage.html#custom-sni-hostname) のAPIに基づきます。

**304テスト合格・2件スキップ**（既存242件＋追加62件）。モックで取得回数・モデル回数・失敗・本文制限・内部接続拒否・転送・DNS枯渇防止・末尾文字を含むURL・空本文・既存API・プライバシー境界を検証しました。構文・依存整合性・差分チェックとwheelビルド成功。サンドボックスからexample.comを1回だけ実取得し、タイトル・本文抽出の成功を確認（観測値約2.81秒。速度保証ではありません）。ライブモデルや本番ツール実行は実施していません。PR保存と本番マージ・デプロイは別であり、未マージ時点では本番反映済みとはしません。
