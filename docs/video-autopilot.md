# Video Autopilot (Phase 2)

The Video Suite provides `POST /api/video/autopilot` as a single-input entry point. It is protected by the existing `KARRY_API_TOKEN` bearer authentication and the upload-size guard. Submit `session_id` and either `novel_text` (up to 12,000 characters), an `image` upload (JPEG/PNG/WebP, up to 4 MiB), or both. A request with neither is rejected. The scene count is fixed at three; the user does not need to configure prompts, voice, aspect ratio, or duration.

The endpoint creates an asynchronous local video job and returns HTTP 202 with its job ID. Existing `GET /api/video/jobs/{job_id}?session_id=...` polling and `/clips/0` download routes apply. The worker asks Gemini for a Japanese narration and three-scene, English visual-prompt plan whose total duration is 15–30 seconds, synthesizes narration per scene, renders each scene with the existing local FFmpeg renderer, joins the WAV audio and MP4 clips, and publishes one final MP4. The generated narration is available through the standard narration route. Text takes precedence as the script source if both text and image are supplied; the uploaded image is still used as each scene's visual base.

An image-only request uses Gemini Vision to infer the scene plan from a sanitized still image. `GEMINI_API_KEY`, FFmpeg, and at least one configured TTS implementation (Gemini TTS, gTTS, or eSpeak NG) are required. Generation errors are recorded against the job without treating a silent video as a successful result. The route uses existing per-session job storage and idempotency via `request_id`.

**Visual scope:** this phase composes videos locally; it does not call a paid text-to-video provider or synthesize new scene artwork. With an uploaded image, that still image is reused across scenes with the existing crop/pan/fade treatment. With text only, the local renderer creates scene-specific title-card visuals from each English visual prompt. The scenes and narration are sequentially joined into a single MP4.
