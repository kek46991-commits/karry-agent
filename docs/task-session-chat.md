# タスク別セッション管理とチャットUI

提供されたFastAPIのセッション管理例とReactのサイドバー仕様を、既存karry-agentへ統合する。FastAPIインスタンスを新設したり、既存エージェントをダミー返答へ置き換えたりしない。現在のHTML UIを再利用し、ビルド依存を増やさず「新しいタスク」「一覧」「選択」「履歴復元」を追加する。

作成・一覧・詳細取得・タスク切替はインメモリだけで処理し、LLMを呼ばない。`/api/chat` の送信時は既存AgentCoreを使い、タスクIDごとに会話・プライベート認証・予定確認・公開確認を分離する。旧 `/chat`、`/run`、`/sessions/{id}` 等を維持し、メモリは同じストアを使う。新しいAPIは既存所有者Bearer認証を要求し、履歴を公開しない。

`app.py` はタスク名・最新公開URL・最後の実行IDと会話メモリを連携し、同一タスクへの同時送信は409で拒否して文脈の混線を防ぐ。公開URLはモデルが書いた文字列から推測せず、実際の公開成功結果だけを記録する。`static/index.html` は既存の濃紺・青アクセント、システムフォント、メッセージ表示・音声・SSE・モニター・HTML公開承認を保ち、左側のタスクサイドバーと選択状態を加える。小画面はタスク一覧・チャット・モニターの縦配置にし、過度なアニメーションや新規画像は追加しない。

この変更はmainの一時公開版から独立PRとして作成し、未マージの永続HTMLストレージPR #9を混ぜない。タスクと履歴も今回の指定どおりインメモリであり、Render再起動で消える。HTML成果物の永続保存とは別の機能である。実装・モック検証・PR保存まで進め、本番マージ・デプロイ・ライブモデル呼び出しは行わない。
