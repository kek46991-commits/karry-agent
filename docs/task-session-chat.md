# タスク管理UIと履歴永続化の統合

## 今回の方針

タスクの作成・一覧・切替・会話表示と、タスク履歴の永続保存を**1つの統合PR**で実装します。PR #9のHTML永続化は作業中にすでにmainへマージされていたため、その最新main（2260667）へ追加機能を統合します。閉じたPR #9へ追記したり、別々のUI版・履歴版PRを作ったりはしません。

方式は**既存の非公開R2/S3バケットへJSONを保存**です。HTMLの永続化と同じS3接続・boto3・鍵を共有するので、別のDB、Vercel連携、Render永続ディスクを新設しません。HTMLは `karry-websites/`、タスクは `karry-tasks/` に分離し、両prefixの重複を拒否します。タスクJSONはFastAPIの一般公開静的ルートへ出しません。

提供されたReactサイドバーの動作は、既存のHTMLチャット画面へ実装しました。FastAPIインスタンスの新設やReactへの全置換、本番Nodeビルドは不要です。既存の濃紺・青アクセント、音声入力／読み上げ、SSE、実行モニター、HTML公開確認を維持しています。Node依存は開発用DOMテストだけです。

## 利用方法

本番コードと保存設定が反映された後、既存のチャットUIを開き、所有者APIトークンを入力して「接続・タスク読み込み」を押します。トークンはブラウザへ保存しません。保存するブラウザ情報は選択中のタスクIDだけです。

初回にタスクがない場合は最初の空タスクを作ります。サイドバーでタスクを新規作成・選択すると、そのIDの履歴と最新公開URLを復元します。切替時は別タスクのメッセージ・モニター・公開確認を残しません。通信や送信中はタスク切替を無効にし、応答の混線を防ぎます。小画面では一覧・チャット・モニターの縦配置です。

一覧・作成・詳細取得・切替ではLLMを呼びません。**メッセージ送信時だけ既存AgentCoreを呼び、ダミー応答へは置き換えません。** 保存された表示用の全履歴と、モデルに渡す短い会話文脈は別です。これまでと同じ、直近の限定された履歴をモデルへ渡します。

## API

新しいAPIはすべて既存 `KARRY_API_TOKEN` のBearer認証を要求します。永続タスクモードでは旧APIもトークン未設定時に503で閉じ、履歴を匿名で読ませません。既存 `/chat`、`/run`、`/agent/run`、`/sessions/{id}` 等は維持します。

| 操作 | API | 動作 |
| --- | --- | --- |
| 作成 | `POST /api/sessions` | `title` を指定。未指定は「新しいタスク」。IDと名前、保存方式を返す |
| 一覧 | `GET /api/sessions` | IDと名前の一覧を保存indexから取得。履歴全文の一括取得やLLM呼出しはしない |
| 詳細 | `GET /api/sessions/{id}` | messages、latest_url、last_run、persistenceを復元 |
| 履歴クリア | `DELETE /api/sessions/{id}/messages` | 会話・last_run・未公開プレビューと、モデルに渡す文脈・プライベートモード認証・保留中の確認を消去。タスク、公開済みURL、次回添付画像は残す。実行中は409。LLMは呼ばない |
| 送信 | `POST /api/chat` | session_idとpromptを指定。既存エージェントと履歴へ接続 |
| ストリーム | 同上、`stream: true` | started／step／completed／errorのSSE。完了には表示用messagesも含む |

```json
{"title": "新しい企画"}
```

```json
{"session_id": "<作成したID>", "prompt": "このタスクの続きを進めてください", "stream": false}
```

JSON返信には従来の `text`、`status`、実行情報と、新しい `response`、`messages`、`title`、`latest_url`、`persistence` を含みます。APIはno-storeです。存在しないタスクは404、入力不正は422、実行競合や容量上限は409、保存設定不足・接続失敗は503です。SSEではHTTP開始後の失敗をerrorイベントで返し、completedとは説明しません。

## 保存されるもの

`karry-tasks/index.json` にタスクIDと名前を保存します。各タスクはIDのSHA256をキーにした `karry-tasks/sessions/<hash>.json` です。JSONバージョン、ID、名前、会話、最新公開URL、最後の実行のメトリクス・回答、実行リースを保持します。ソースコードやGitへ会話データを書き込みません。

完了済み会話の永続ログは最大1000メッセージ・1タスク2 MiBです。上限で古い履歴を勝手に切り捨てず、停止して新しいタスクの作成を案内します。モデル文脈用のインメモリキャッシュは直近20メッセージ以内に絞ります。タスク数は100件。チャット見出しの「🗑 履歴をクリア」は「会話履歴を消去しますか？」の確認後に上の履歴クリアAPIを呼び、そのタスクを空の状態で表示し直します。保存済み画像の実体は消さないため、画像の保存枠も空けたい場合は新しいタスクを作ってください。タスク自体の削除・名前変更・無制限保管・全文検索は今回の機能に含めません。

保存時に実値のAPI鍵・Token・合言葉を除去します。個人的な会話そのものは非公開バケットへ保存する利用者データです。バケットやindexを一般公開しないでください。公開HTMLと同じバケットなので、バケット全体の一般公開を有効化すると履歴保護を壊します。

プライベートモードの認証済みフラグ、CalendarやHTMLの未承認操作、公開承認IDの有効状態は永続化しません。再起動後に認証は再確認し、未承認操作は再準備します。保存された過去の会話を理由に、自動的に再実行・公開することはありません。実行トレースの大きなHTML全文は履歴JSONへ複製せず、最後の実行概要を保存します。

最新URLはモデルの返答文字列から推測しません。所有者が公開を承認した時点で、公開前にファイル名・SHA256・URLの意図をタスクJSONのoutboxへ保存します。その後にHTMLを公開し、成功を確定します。直接公開APIではトップレベル `session_id` を指定すると同じ処理を行います。URL確定に失敗しても意図が残るため、次のタスク詳細取得で実際のHTMLとハッシュを照合して元タスクのURLを復旧します。復旧は既存データを読むだけで、新しい公開を自動実行しません。存在しない／ハッシュが異なるHTMLを公開済みとは説明しません。未確認outboxは最大20件です。

## 競合と障害

JSON更新はETag／If-Match、新規保存はIf-None-Matchを使い、競合時だけ上限3回のCASを行います。MD5、SHA256、サイズ、UTF-8／JSON構造を検証します。読み取りストリームも閉じます。単一プロセスのロックに加え、共有オブジェクトの30分リースを取得してからモデルを呼ぶため、別インスタンスから同じタスクを同時実行させません。

リースの所有権・期限を確認して完了履歴を保存します。保存失敗を成功として返さず、モデルや副作用ツールを自動再実行しません。PUT応答だけが失われた場合は読み取り照合で保存結果を確認します。checksum付きPUTの成功応答とETagを取得済みの場合、追加の確認GETの一時障害だけで書込みを未実行扱いに戻しません。通常終了時のリースは解除されます。突然のプロセス停止では、完了済みの履歴は残りますが、未完了応答は確定せず、残存リースは最長30分待ちになります。自動で途中実行を再開する機能ではありません。

`/api/chat` は任意 `request_id` を受け取ります。UIは同じ入力の手動再送で同じIDを使い、最新完了リクエストのID・入力のハッシュが一致すれば保存済みの回答を返してモデルを呼びません。同じIDで異なる入力を送ると409です。再送IDは平文でなくハッシュとして保存します。これは最新完了リクエストの照合であり、無制限の過去リクエスト台帳ではありません。旧クライアントがIDを省略した場合、この再送照合は利用できません。

タスク本体と一覧indexは別オブジェクトであり、全体をDBトランザクションにはしていません。作成途中の障害でindexへ未登録の初期オブジェクトが残る場合がありますが、既存履歴を上書き・削除しません。一般公開HTMLの保存とも別トランザクションです。大規模な多人数サービスや厳密な分散クォータが必要になった場合は、DB基盤への移行が適切です。現在は単一所有者用の小規模構成です。

## 管理者設定

HTML永続化用に登録した次の設定をそのまま共有します。鍵をチャット、Git、スクリーンショットへ貼らないでください。

- `KARRY_WEBSITE_S3_BUCKET`
- `KARRY_WEBSITE_S3_ENDPOINT`（R2）／`KARRY_WEBSITE_S3_REGION`
- `KARRY_WEBSITE_S3_ACCESS_KEY_ID`／`KARRY_WEBSITE_S3_SECRET_ACCESS_KEY`
- `KARRY_WEBSITE_S3_SESSION_TOKEN`（AWS一時資格情報の場合のみ）

追加は非秘密の2項目だけです。

```dotenv
KARRY_TASK_STORAGE=s3
KARRY_TASK_S3_PREFIX=karry-tasks/
```

鍵には専用バケット内のJSONのGet・Put、HTML用のGet・Put・Listが必要です。タスク専用prefixへのアクセスも許可してください。既存の鍵がHTML prefix限定の場合は権限設定を管理者が確認します。今回、鍵や本番アカウント設定は変更していません。R2／S3設定不足時にローカルJSONやメモリへ黙って戻りません。

ローカルの一時開発だけ `KARRY_TASK_STORAGE=memory` を明示できます。この場合は再起動で消える警告をUIへ表示します。通常の利用者は新しいサービスの接続設定を行いませんが、管理者のバケット・鍵設定は必要です。

## テストと本番切替

Pythonの既存回帰、S3互換モック、実SDKパラメーター、FastAPI経由の再起動相当復元、DOMの切替・認証・SSEを1つのCIで実行します。テストは外部バケットや本番モデルへ接続しません。

```bash
.venv/bin/python -m pytest -q
npm ci --ignore-scripts --no-audit --no-fund
npm run test:ui
```

この実装のPR保存と、本番へのマージ・設定・実再起動確認は別です。現在のRenderの公開URLに今回のUIが反映済みとは説明しません。既存の一時HTML・旧インメモリ履歴は、失われた後に復元することはできません。未移行の既存HTMLは再デプロイ前の退避・移行を実施してください。HTML側の手順は [durable-website-storage.md](durable-website-storage.md) を参照してください。
