# 成果物・リソース取得の安全なエラー処理

## 症状と原因

本番の `/static/instant/{filename}` は、存在しない成果物へアクセスすると404と英語のJSONを返していました。ヘルスとチャット画面は正常で、404自体はサーバープロセスのクラッシュではありません。本番の旧サンプルは一時保存時代のURLであり、再デプロイ後にデータが見つからない状態を確認しています。

修正では **欠落を404、保存先障害を503、予期せぬ取得失敗を500** として明確に区別します。存在しない成果物やタスクを架空の成功データ、空の会話やHTTP 200で置き換えません。

## ブラウザとAPI

公開成果物やページをブラウザで開くと、日本語の案内と「チャット画面に戻る」リンクを表示します。生の英語JSONは表示しません。固定のサーバーコピーだけを表示し、ファイル名・URL・例外・資格情報・ユーザー入力をHTMLへ埋め込みません。JavaScriptや外部リソースに依存しない、スマートフォン対応のページです。

APIや `Accept: application/json` の取得では、例えば次のJSONとHTTP 404を返します。

```json
{
  "status": "not_found",
  "detail": "指定された成果物が見つかりません。",
  "error_code": "artifact_not_found",
  "resource_type": "artifact",
  "hint": "公開URLをご確認ください。再起動前の一時保存データや未公開の成果物は、このURLでは取得できません。",
  "recovery_url": "/"
}
```

セッション・画像・実行記録の既存取得経路も日本語の案内へ統一します。タスク保存の既存 `error_code: not_found` は互換性のため保持します。private APIをブラウザで開いてもJSONと所有者認証を維持し、匿名へ履歴を公開しません。

## 障害と境界

| 状態 | 応答・動作 |
| --- | --- |
| 成果物・タスク・画像・実行記録が存在しない | 404、明確な日本語案内。自動再生成・代替タスク作成なし |
| R2/S3の接続・読み取り障害、ローカルの権限・破損 | 503、再読み込みと保存先確認を案内。削除と断定しない |
| 予期せぬ取得エラー | 500、固定の安全なメッセージと診断記録。生の例外を返さない |
| 正常な公開成果物 | 200、元のHTMLと既存CSP隔離を維持 |
| 所有者APIの未認証・誤トークン | 従来どおり401。エラーの見栄えのために認証を無効化しない |

静的配信の別名経路も同じ処理へ接続します。GET/HEADに対応し、HEADは本文を送らずGETと同じ状態・長さ情報を返します。エラー応答は `Cache-Control: no-store` として、新しく保存されたデータの取得を古い404キャッシュで妨げません。画像やスクリプトのエラーへHTMLを注入しません。

ローカル成果物は512 KiB以内の通常ファイルだけを、symlink追従なしで応答送信前に読み終えます。検証と配信の間にファイルが消えた場合は404を返します。途中で読み込みエラーとなった内容を200や半端なHTMLで送信しません。既存のR2永続保存からローカル保存への自動フォールバックは追加しません。

FastAPIのHTTPExceptionは意図した状態のまま扱い、例示コードのように404をcatch-allで500へ変えることはしません。HTTP例外の内部パス・署名情報等も返さず、必要な認証・Retry-Afterヘッダーのみ維持します。作業中にmainへ追加された `/api/artifacts/{filename}` は所有者限定の公開状況確認APIとして維持します。この診断APIの `200/published:false` は成果物の取得成功ではなく、未公開・欠落を明示する診断結果です。読取り障害はここでも503に区別します。
