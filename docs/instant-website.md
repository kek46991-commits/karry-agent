# HTML成果物のインスタント公開

`deploy_instant_website(html_content, filename=None)` を追加しました。GitHub Token、Git push、追加の外部公開サービスを使わず、FastAPIが配信する `static/instant/` へHTMLを直接保存し、`/static/instant/<名前>_<ランダムID>.html` のURLを返します。Gitリポジトリの有無やGit CLIに依存しません。

**これは稼働中の本番ドメインから配信される一時プレビューです。永続ホスティングではありません。** Renderの再起動・再デプロイ・インスタンス切替で消える可能性があります。複数インスタンス間でも共有しません。今回はローカルファイルだけを使う要件のため、外部ストレージや永続ディスクは追加していません。

## 既存チャットで使う

HTML成果物を作って公開したいと依頼すると、モデルは `deploy_instant_website` ツールでHTML全文、予定公開URL、SHA256を準備し、`needs_user_action` で停止します。この段階ではまだ公開していません。

チャット画面に表示されるHTML全文と公開先を確認し、公開承認のチェックを入れて「確認した内容を即時公開」を押してください。既存のAPIトークンを使い、提示された内容だけを即時公開してリンクを返します。GitHub等の新しい接続設定は不要です。確認は10分有効で、期限切れ・再起動の場合は再度準備してください。モデルが `confirmed=true` を生成しても公開承認にはなりません。

不特定の利用者が閲覧可能な内容になるため、個人情報や秘密情報が含まれないことを公開前に確認してください。チャットはHTMLソースをテキストとして表示し、確認画面内では実行しません。

## 所有者がHTML全文を直接指定するAPI

所有者が確定したHTMLを明示的に送る場合、既存のBearer認証付き `POST /api/agent/tools/execute` から即時公開できます。これはモデルによる自動自己承認とは別で、送信内容そのものが公開対象です。新しい外部サービスのTokenは不要ですが、既存APIの所有者認証は省略しません。

```json
{
  "tool_name": "deploy_instant_website",
  "arguments": {
    "html_content": "<!doctype html><html lang=\"ja\"><head><title>Demo</title></head><body><h1>Sample page</h1></body></html>",
    "filename": "sample_website.html"
  }
}
```

`result.success` と `result.status` を確認してください。成功時の `public_url` は `RENDER_EXTERNAL_URL` を基準にします。Render自身がこの変数を設定するため、利用者の追加設定は不要です。未設定時の既定値は `https://karry-agent-1.onrender.com`。Render以外で動かす場合はホスト管理者が実際のオリジンを設定する必要があります。関数をサンドボックスだけで呼んでも、Renderへファイル転送されるわけではありません。

確認待ちのAPI利用では、プレビューで受け取ったIDとSHA256を、既存Bearer認証付き `POST /api/agent/websites/confirm` へ送ります。

```json
{
  "approval_id": "<プレビューのapproval_id>",
  "sha256": "<プレビューのsha256>",
  "confirmed": true
}
```

`confirmed=false` はキャンセルです。確認後の内容、公開先変更、リプレイ、期限切れを検査します。このAPIはモデルツールとして登録していません。

## 保存・配信と制限

既存チャットの `static/index.html` は変更・上書きしません。実際のFastAPI静的ルートを保存関数へ渡し、ソースツリーとインストール先の違いによる誤った保存先を避けます。希望名を英数字・ハイフン・アンダースコアへ正規化し、毎回ランダムIDを付けます。内容を書き終えた後に最終パスへ原子的に追加し、既存ファイルを置き換えません。サーバー内部の絶対パスは返しません。

HTMLはUTF-8、最大512 KiB、最大128ファイル・合計32 MiB。確認待ちは最大20件・10分有効です。容量上限時はエラーを返し、既存成果物を自動削除しません。実値を含むToken、合言葉、環境変数の非公開呼称・私的コンテキストは公開を拒否します。ただし一般的な個人情報を完全に自動判定する機能ではなく、全文確認は必要です。

公開ページには `Content-Security-Policy: sandbox allow-scripts` を付け、`allow-same-origin` を与えません。生成スクリプトはアプリの認証情報やストレージへアクセスできない独立したオリジンとして動きます。フォーム送信、接続API、埋込みフレーム等も制限します。inline JavaScriptによるローカルのインタラクション、CSS、HTTPS画像・フォント等は利用できますが、バックエンドAPIへ接続する動的Webアプリをフル機能で配信する仕組みではありません。

静的URLの別表記・正規化経路にも同じ隔離ヘッダーを適用します。`nosniff`、`no-store`、`no-referrer` を指定。一時HTMLはGitとDockerビルド対象から除外しています。

## 検証と配置

**348テスト合格・2件スキップ**（既存304件＋追加44件）。ローカルHTTPで保存したHTMLを取得し、内容と隔離ヘッダー、既存画面の応答を確認しました。所有者認証・モデルの未公開確認待ち・容量・入力・秘密値・SHA256・期限・キャンセルも検証。公開前URLが404で原子的な保存後だけ200になること、未管理・作業中ファイルが別表記URLでも404となることを確認。Python構文、JavaScript構文、依存整合性、差分チェック、wheelビルド成功。

実装PRと本番コード配置は別です。未マージの間は本番エージェントにこのツールはありません。今回は本番成果物を公開せず、GitHub公開用コードだけをPRへ保存します。コードが本番へ反映された後は個別成果物の公開にGitHub更新・再デプロイは不要です。
