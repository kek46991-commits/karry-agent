# GitHub auto-sync safety workflow

Karry-Agent adds `GITHUB_AUTO_SYNC_SYSTEM_PROMPT` to its normal AgentCore system instruction and exposes a structured `run_git_command` tool. The tool accepts an operation enum—not a shell command string—and executes argument arrays with `shell=False` in the configured `KARRY_WORKSPACE` (or the process working directory). It never installs Git/GitHub CLI automatically and does not accept a caller-selected filesystem root.

The operations are `version`, `status`, `remotes`, `branch_info`, `initialize`, `add_remote`, `create_branch`, `stage`, `review`, `commit`, `push`, and `create_pr`. New repositories require `confirm_initialization=true` and start on an `agent/...` branch. Adding `origin` requires `confirm_remote_change=true` plus an exact credential-free GitHub HTTPS/SSH URL; an existing `origin` is never replaced. Branch creation requires a clean working tree, fetches `origin/main`, and refuses local or remote name collisions.

Staging requires individually listed relative paths; globbing, whole-repository staging, common credential files, and generated dependency/cache directories are blocked. Review returns a bounded, redacted staged diff. Commit requires an exact match between the reviewed path list and staged paths, a clean diff check, a non-main branch, and `confirm_reviewed_diff=true`. Push targets only the current feature branch and never uses force; an existing upstream is updated only when it is configured as `origin/<same-branch>`, allowing Git's normal fast-forward checks to reject divergence. PR creation is fixed to base `main` and requires a pushed branch, a clean worktree, GitHub CLI authentication, and review confirmation.

The tool does not merge PRs, deploy production, overwrite remotes, reset/discard user changes, or resolve non-fast-forward conflicts by force. If Git, GitHub authentication, or repository permissions are unavailable, the agent reports what is missing and does not claim synchronization succeeded.
